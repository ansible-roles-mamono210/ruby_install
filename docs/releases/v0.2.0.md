# ruby_install v0.2.0 candidate

This candidate installs source-built Ruby on CentOS Stream 9 x86_64 and preserves
an existing installation on an identical rerun. The default is Ruby 3.4.12 in
`/opt/ruby` with standard documentation. No public command links are created.
Call the tools under `<prefix>/bin` directly. The [installation example](../../README.md#installation-example-for-v020)
shows the required facts, root privileges and typed inputs.

## Installation record

The compatibility baseline for v0.2.0 is the UTF-8 JSON file
`<prefix>/.ruby-install-state.json`. The Role writes it after verifying the
new installation. A later Role must be able to read records produced by v0.2.0.

| Field | Schema 1 |
| --- | --- |
| `schema_version`, `state` | Integer `1` and string `"complete"` |
| `ruby_version`, `canonical_prefix` | Full Ruby version and resolved absolute prefix |
| `source_sha256` | SHA-256 of the downloaded tar.gz as 64 lowercase hex digits |
| `shared`, `documentation` | JSON booleans. The supported build uses `shared: true`. `documentation` records the install-time choice. |
| `jit` | For Ruby 3.4, `{"yjit": false, "rjit": false}`. For Ruby 4.0, `{"yjit": false, "zjit": false}`. |

The reader checks the exact keys and types, the owner and permissions, the build
contract and the installed Ruby. All six recorded installations produced this
format. v0.3.0 must demonstrate compatibility with an actual v0.2.0 record
before adding links to an existing installation.

## Migration and recovery

- Replace the five [legacy variable names](../../README.md#migration-from-earlier-names)
  wherever they are visible to the Role, including inventory and other roles.
  Set the dedicated prefix and documentation choice before the first run.
- Leave the existing OS Ruby or legacy install in place. Select a separate,
  empty dedicated prefix for the new Role. Test the absolute paths to `ruby`,
  `gem` and `bundle` in each consuming service before switching it over. Review
  application gems and any commands created by them separately.
- On a stop, record the reason and any private workspace path in the Role
  output. Inspect the prefix, record and relevant link targets. Save needed
  application data, gems and any `configure.log`, `build.log` or `install.log`
  before moving files. After a checksum or redirect failure, correct the source
  URL or checksum before retrying. Earlier dependency or CRB changes may persist.
- A version or build-contract mismatch requires the original inputs or a new
  dedicated prefix. For an incomplete or unmanaged installation, stop affected
  services and back up the identified prefix before moving it aside. Start the
  new installation in a vacant prefix. Leave record creation to the Role.
  If a residual public link points into the prefix, confirm its consumer and
  destination before unlinking that one entry. Remove a retained build workspace
  only after collecting its logs and verifying it belongs to the failed run.

### Supplementary candidate checks

The fixed controller also exercised the updated checks locally against a CentOS
Stream 9 x86_64 target using a chroot connection. Ruby 3.4.12 was built from the
checksum-pinned source served by a loopback HTTPS mirror, with documentation
off, four build jobs and workspace retention on. Installation, check mode and
an identical normal run reported `changed=3/0/0` and `failed=0`. The RPM-owned
Ruby 3.0.7 under `/usr/bin` retained its path, version, package, ownership,
permissions and binary hash. The private workspace retained all three build
logs, and its sibling file kept its original contents. The managed prefix,
public commands, RPM inventory and repository files had identical hashes after
installation, check mode and the normal rerun.

Separate Role runs stopped on one bad checksum, three redirects and one
configure failure. Each source received one request. Redirect destinations
received zero connections. All five private workspaces and their sibling files
remained available, including the expected diagnostic in the failed configure
log. A target with a noexec workspace also produced the specified preflight stop.
