# ruby_install v1.0.0

The first stable release was published on 2026-11-26. Ruby 3.4.12 and 4.0.9
were verified on CentOS Stream 9 x86_64. The default installs Ruby 3.4.12 under
`/opt/ruby` with standard documentation and uses the commands from `/opt/ruby/bin`.

## Install a specific revision

In a new playbook directory on the controller, clone the release tag. The
expected commit is `057658e284ae63769722d0c47116b41fb0e5b3f6`.
[Controller and target requirements](../../README.md#scope-and-execution-requirements)

```sh
git clone --branch v1.0.0 --single-branch https://github.com/ansible-roles-mamono210/ruby_install.git roles/ruby_install &&
  git -C roles/ruby_install rev-parse HEAD
```

Place the [installation play](../../README.md#installation-example)
beside the `roles/` directory. Set the inventory and run the play for the intended
hosts. Keep the prefix and documentation setting used when Ruby was installed.

## Migrate an existing installation

| Starting point | Example |
| --- | --- |
| v0.2.0 with Ruby 3.4.12 under `/opt/ruby` | Keep the original settings. To publish commands, set `ruby_install_create_symlinks: true` and `ruby_install_symlink_commands: [ruby, gem]`. Check mode previews the missing links. A normal run adds them. An identical rerun reuses them. |
| v0.3.0 with `bundle` and `rake` already published | Keep both in the list. Use `[bundle, rake, ruby, gem]` to add `ruby` and `gem`. Verify the original links still resolve to the same prefix. |
| Legacy Role or OS-managed Ruby | Replace visible [legacy input names](../../README.md#migration-from-earlier-names). Pick a separate vacant prefix and initially leave links off. Run the application with that prefix's absolute executable before switching its service configuration. |

For a v0.3.0 installation under `/opt/ruby-custom`, run these commands on the
target before and after the change. The two links should resolve to
`/opt/ruby-custom/bin/bundle` and `/opt/ruby-custom/bin/rake`.

```sh
readlink -e /usr/local/bin/bundle /usr/local/bin/rake
/opt/ruby-custom/bin/ruby --version
```

Application gems may install their own commands. Use their absolute paths or
set the application's PATH. The Role publishes only its nine supported names.

## Recover from a stop

- **A smaller link list stops with `RESIDUAL_LINK`.** For example, when keeping
  `ruby` and dropping `gem`, inspect `readlink /usr/local/bin/gem`. Move consumers
  to the intended executable. Once other link writers are idle, the following
  command removes just this symlink if it still points directly at the expected
  binary. Rerun with `[ruby]` after checking the remaining names.

  ```sh
  if [ -L /usr/local/bin/gem ] && [ "$(readlink /usr/local/bin/gem)" = /opt/ruby/bin/gem ]; then
    unlink /usr/local/bin/gem
  fi
  ```

- **A build failed or the prefix has an incomplete record.** Note the prefix
  and private workspace printed by the Role. Inspect the record, back up the
  prefix and any application gems, and save available `configure.log`,
  `build.log` and `install.log`. Stop or switch consumers and release only their
  confirmed links before moving the identified prefix aside. Correct the
  failure and rerun with the intended prefix vacant. The Role writes the
  completed record after verifying the new installation.
- **The requested Ruby version or build settings differ.** To reuse the
  existing prefix, restore the inputs recorded in it. To change from Ruby
  3.4.12 to 4.0.9, use a separate dedicated prefix (for example
  `/opt/ruby-4.0.9`) with publication off. Test that prefix in the consuming
  application before switching its command paths.
