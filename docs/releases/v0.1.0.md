## Contents and limitations

This development snapshot freezes Phase 1 specifications, evaluation tooling
and historical evidence. It includes the legacy Role for source continuity.
That Role does not implement the new ten-variable interface, verified download,
managed-prefix decisions, safe reruns, installation records or link publication.
The first planned implementation release is v0.2.0.

See the [README](../../README.md), [changelog](../../CHANGELOG.md) and
[evidence ledger](../p1-evidence.md). No production installation instructions are
provided for the unimplemented contract. Removing unverified metadata declarations
does not establish compatibility with additional Ansible versions or EL systems.

## Candidate validation

The proposed execution is one run of each job on `plan/ruby-100-p1-env-r1`,
using `run_v010_release_checks=true` and both P1 probe parameters false.
Default pushes to that branch do not run this workflow. Mixed parameters select
no workflow and do not constitute success. New jobs explicitly ignore tags;
their approval is tied to the branch candidate SHA. Existing workflow job lists
and default parameter behavior are retained.

| Job | Fixed environment | Coverage |
| --- | --- | --- |
| `v010-static-and-probes` | Python 3.14.10 / core 2.21.6 | Collect 582 methods; real Ansible acquisition module tests; source/diff and distribution checks; independent public Git fetch by candidate SHA |
| `v010-lint-controls` | Python 3.14.3 / core 2.20.3 / ansible-lint 26.1.1 | Two dedicated files, 20 methods, including the six required real lint methods; zero skips |

Controller image: `ghcr.io/docker-images-mamono210/circleci-executors/molecule-docker@sha256:a80f2c478e9e183cdd782f8cdff79d1025cdc5291190e360898738fd8e6f7f41`.

Lint image: `ghcr.io/docker-images-mamono210/circleci-executors/ansible-lint@sha256:4ea7fe7ebbe7fd06bd5a7fc61b8931c3303a11c9bd4eb06431a810f5914b8718`.

Both jobs use Docker `small`, an explicit 10-minute command limit and a 30-second
TERM-to-KILL interval. `no_output_timeout` is 11 minutes and is not the runtime
limit. These are configuration values, not a verified bill or total job budget:
image startup, checkout and artifact upload are outside the command limit.
Check actual pricing, balance, the two-job estimate and execution authorization
before starting. There is no automatic retry and no inherited 1500-credit budget.

`v010-evidence` records the candidate SHA, configured image and observed versions,
source hashes, collected/started/passed/skipped test IDs, results and fixture
directory cleanup. The six lint-only IDs may be skipped on the controller; the
same IDs must pass on the lint job. The 20 lint methods overlap the controller's
582; do not report 602 independent successful tests. Unexpected skips, expected
failures, unplanned source changes or environment mismatches fail the check.
These naming tests deliberately reject legacy names and are not whole-Role lint.

The runner uses a private temporary directory. Normal completion and command
timeout remove that directory; GNU timeout terminates the command process group.
Unexpected cancellation or agent failure still requires checking evidence and
executor disposal. A missing result/cleanup artifact is not successful cleanup.
No Role installation, target container or Ruby build is run by these two jobs.

The controller requires all seven distribution files, finalized `BSD-3-Clause`
metadata and unchanged Role/evaluation scripts relative to the baseline. Three
regression-test changes are separately pinned by SHA-256 in the runner. The CI-only
checker is `scripts/release/check_v010.py`; the command calls that file directly
to avoid interpreting shell heredoc syntax as a CircleCI expression. The
runtime host mock follows the configured temporary root instead of assuming
`/tmp` directly; its assertions and the CI cleanup boundary are unchanged. It
checks LICENSE presence and the metadata identifier. Those fields are now
prepared. The holder's confirmation supplies the ownership/provenance decision;
file checks do not establish it independently. Final document consistency remains
part of V010-01; actual fixed-image CI is still pending.

The independent fetch compares the full committed file list and SHA-256 hashes
with checkout. It does not create or validate a release tag. Config parsing and
local workflow-condition checks alone are not CircleCI execution evidence.
