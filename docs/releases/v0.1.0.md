# ruby_install v0.1.0 — development snapshot

Release notes for the Phase 1 specification and evaluation snapshot. The
published GitHub Pre-release identifies the exact approved commit and final
verification record. These files alone do not establish that publication has
occurred; verify the `v0.1.0` tag against that published commit.

## Contents and limits

This snapshot freezes the adopted Phase 1 specification, evaluation tooling
and historical evidence for the future Ruby installation Role on CentOS Stream 9.
It includes the legacy Role for source continuity. That Role does not implement
the new ten-variable interface, verified acquisition, managed-prefix decisions,
healthy reruns, installation records or link publication. The first planned
installation-capable release under that contract is v0.2.0.

See the [README](../../README.md), [changelog](../../CHANGELOG.md) and
[evidence ledger](../p1-evidence.md). Metadata omits unverified minimum-version
and general EL compatibility claims. This does not establish support for every
Ansible version or EL system. The main-branch badge is not candidate CI evidence.

The distribution includes [BSD-3-Clause](../../LICENSE),
Copyright (c) 2021 mamono210. The holder confirmed that the existing code was
self-written and selected the initial-commit year. CI checks the LICENSE file
and metadata identifier; it does not independently establish ownership.

## Reproducing the limited checks

The workflow runs on `plan/ruby-100-p1-env-r1` with
`run_v010_release_checks=true` and both P1 probe parameters false. Default pushes
do not run it. Mixed parameters select no workflow and do not constitute success.
The two jobs ignore tags. Existing normal/P1 workflow behavior is retained.

Controller image:
`ghcr.io/docker-images-mamono210/circleci-executors/molecule-docker@sha256:a80f2c478e9e183cdd782f8cdff79d1025cdc5291190e360898738fd8e6f7f41`.

Lint image:
`ghcr.io/docker-images-mamono210/circleci-executors/ansible-lint@sha256:4ea7fe7ebbe7fd06bd5a7fc61b8931c3303a11c9bd4eb06431a810f5914b8718`.

Both jobs use Docker `small`, a 10-minute validation-command timeout, a
30-second TERM-to-KILL interval and an 11-minute no-output timeout. Image
startup, checkout and artifact upload are outside the command timeout. There
is no automatic retry. Confirm current pricing, balance and the authorized
execution scope before starting another run.

`scripts/release/check_v010.py` records candidate/source hashes, observed
versions, collected/started/passed/skipped IDs, results and independent fetch.
Unexpected skips, expected failures, source changes outside the allowlist or
environment mismatches fail the check. Three regression-test files are pinned
by SHA-256; the runtime host mock respects the configured temporary root.
Role and Phase 1 evaluation scripts retain their baseline content.

The command uses a private temporary directory and an EXIT cleanup trap.
CI462 confirms cleanup after normal completion, not an induced timeout test.
Cancellation or agent failure still requires examining cleanup evidence and
executor disposal. No Role installation, target container or Ruby build is
performed by these two jobs.

## Publication boundary

Before publishing, complete the final document review and the final candidate's
V010-01 through V010-07 verification record. Approval identifies the exact SHA,
tag `v0.1.0`, Pre-release body and operations. The published body records the
final SHA and CI result; updating this source file after a successful final CI
is not required solely to insert those identifiers.

Create the tag at the approved SHA, retrieve the tag separately and compare its
commit and all files, then publish the GitHub Pre-release for that tag. Read
back tag/SHA, body and Pre-release status (V010-08). If tag retrieval fails, stop
before publishing the Pre-release and do not move the tag.

The candidate comes from the evaluation branch. Main merge and Galaxy publication
are outside this snapshot's scope. v0.2.0 implements Phases 2+3; v0.3.0 adds
Phase 4 links; v1.0.0 completes the contract and release validation. The six
real-Role conditions and normal four CI categories remain future requirements.
